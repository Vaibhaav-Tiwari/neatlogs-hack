Meet Tally

the CFO for your agent fleet

Hand it your GitHub issues and a budget. It picks a cost-effective model for each one, stops any task at its spend ceiling, and opens a pull request only when your tests pass.

Install Tally

One line and it is on your machine.

$ npm install -g tally-agents

Needs Node 20 or later. The package is tally-agents; the command it installs is tally. Then, in an empty folder:

tally demo        # seven simulated tasks, no accounts or keys
tally dashboard   # watch the ledger fill in

tally-agents on npmSource on GitHub

What Tally does

  1. Routes each GitHub issue to a cost-effective model.
  2. Caps spend per task.
  3. Escalates to a stronger model if needed.
  4. Verifies the change with your tests.
  5. Opens a pull request. Tally never merges.

Three switches

  • Entire. Off: a task is sized by a search of the repository. On: sized from the code graph, with a checkpoint attached to each commit.
  • neatlogs. Off: no trace. On: a decision trace and a worker trace id on every ledger row.
  • cfo.ai. Off: the budget is typed into tally.yaml. On: the live monthly budget is read from cfo.ai, and spend is written back and reconciled to the ledger.

The working switches and the sample run they redraw are being built.

Better with a conductor.

With Agent Orchestrator, Tally runs agents in parallel. Without it, Tally runs Claude Code or Codex directly, one task at a time.

With Agent Orchestrator

Several tasks at once, each agent in its own worktree. tally init finds Agent Orchestrator and sets it up as the runner.

Without it

Tally starts Claude Code or Codex itself and works through the tasks one at a time. No Agent Orchestrator needed.
