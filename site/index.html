Meet Tally

the CFO for your agent fleet

Hand it your GitHub issues and a budget. It picks a cost-effective model for each one, stops any task at its spend ceiling, and opens a pull request only when your tests pass.

Install Tally

Install

$ npm install -g tally-agents

Needs Node 20 or later. The package is tally-agents; the command it installs is tally.

Five moves on every issue.

#17

  1. Route

    Routes each GitHub issue to a cost-effective model.

  2. Cap

    Caps spend per task, and stops the agent at the ceiling.

  3. Escalate

    Escalates to a stronger model if needed, on the same branch.

  4. Verify

    Verifies the change by running your tests itself.

  5. Pull request

    Opens a pull request for the work that passed.

Tally never merges. That decision stays with you.

Three switches.

Tally runs on its own. Each of these adds something to the same run when it is on. Flip them and watch one real run change.

Entire

Off. A task is sized by a search of the repository.

On. Sized from the code graph, and a checkpoint is attached to each commit.

neatlogs

Off. No trace.

On. A decision trace and a worker trace id on every ledger row.

cfo.ai

Off. The budget is typed into tally.yaml.

On. The live monthly budget is read from cfo.ai; spend is written back and reconciled to the ledger.

Better with a conductor.

With Agent Orchestrator, Tally runs agents in parallel. Without it, Tally runs Claude Code or Codex directly, one task at a time.

With Agent Orchestrator

Several tasks at once, each agent in its own worktree. tally init finds Agent Orchestrator and sets it up as the runner.

Without it

Tally starts Claude Code or Codex itself and works through the tasks one at a time. No Agent Orchestrator needed.

The mascot is Agent Orchestrator's, from OrchestratorInc/agent-orchestrator (Apache-2.0), shown here in a painted scene.
