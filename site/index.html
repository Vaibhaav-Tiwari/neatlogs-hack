What it does

Five steps for every issue

  1. Route

    Routes each GitHub issue to a cost-effective model.

  2. Cap

    Caps spend per task, and stops the agent at the ceiling.

  3. Escalate

    Escalates to a stronger model if needed, on the same branch.

  4. Verify

    Verifies the change by running your tests itself.

  5. Pull request

    Opens a pull request for the work that passed.

Tally never merges. That decision stays with you.

Integrations

Three switches, one run

Tally runs on its own. Each of these adds something to the same run when it is on.

Entire

Off. A task is sized by a search of the repository.

On. Sized from the code graph, and a checkpoint is attached to each commit.

neatlogs

Off. No trace.

On. A decision trace and a worker trace id on every ledger row.

cfo.ai

Off. The budget is typed into tally.yaml.

On. The live monthly budget is read from cfo.ai; spend is written back and reconciled to the ledger.

Agent Orchestrator

In parallel through Agent Orchestrator, or one at a time

With Agent Orchestrator

Tally can run agents in parallel, each in its own AO session and worktree. It is opt-in (tally run --parallel 3) and stays inside one budget: each task's ceiling is reserved before it starts.

Without it

Tally runs Claude Code or Codex directly, one task at a time. Parallel runs need Agent Orchestrator.

tally init detects which you have. Mascot from OrchestratorInc/agent-orchestrator, Apache-2.0.

Usefulness and originality

“Whether the agent solves a problem that people have, in a new way.”

A spending limit per task, not per person

Each task gets its own ceiling before it starts, a cheaper model is tried first only when that is the lower expected cost, and an agent that crosses its ceiling is stopped. The ledger ties every attempt to its tokens, its cost and its pull request.
